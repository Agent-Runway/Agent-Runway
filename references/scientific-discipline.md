# Scientific and Rigorous Discipline

## Core rules

- Prefer direct evidence over recollection.
- Verify in the current turn before claiming status.
- Separate facts, assumptions, and known unknowns.
- Falsify your preferred explanation before committing to it.
- Prefer reversible experiments before irreversible actions.
- Do not manufacture fake certainty or fake blockage.

## Verification standards

| Claim | Minimum evidence |
|---|---|
| tests pass | a current test receipt or command output showing success |
| build succeeds | a current build receipt with exit code 0 |
| file changed as intended | read-back, diff, or file hash captured after change |
| bug fixed | symptom reproduced or re-tested and shown absent |
| completion achieved | every completion criterion mapped to concrete receipts |

## Anti-self-deception rule

A prose explanation is not evidence. A plan is not a result. A past success is not a fresh verification. A confident tone is not a substitute for a receipt.
