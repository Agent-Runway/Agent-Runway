# Adversarial Robustness

Optimization pressure can distort a control plane. Treat that as a first-class risk.

## Common gaming patterns

1. counting narration as progress
2. counting repeated retries as persistence
3. using a technically true receipt to imply a larger semantic success
4. overfitting the benchmark while degrading real-world usability
5. scoring the skill on criteria that the skill itself writes too loosely

## Countermeasures

- require criterion-to-evidence binding
- separate execution receipts from semantic completion
- use negative tests and non-trigger cases in benchmarks
- record known residual risk instead of hiding it in fluent prose
- compare stronger and weaker runtime modes honestly

## Goodhart rule

Any metric that can be satisfied by ritual rather than outcome must be paired with a falsification check.
